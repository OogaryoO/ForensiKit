# 專案計畫

## 目標

PoC 要證明：**資訊室人員能在 10 分鐘內，於 Windows 匯出只含指定時段、可交付鑑識的證據包。**

適用情境：主機疑似遭入侵、仍可開機且尚未修復時（拔網路線不關機 → 匯出 → 交付 → 修復）。
不適用：已關機主機、記憶體鑑識、多主機同步收集、Linux。

## 範圍

| 做 | 不做（列為延伸） |
|---|---|
| Windows 10/11、PowerShell 5.1 | Linux、macOS、Windows Server／AD 專屬紀錄 |
| 常駐保全：加大 log 上限＋定時備份 EVTX 到 vault | 遠端派送、多主機收集 |
| 依時段裁切 EVTX（wevtutil） | $MFT、USN Journal、被鎖定的登錄 hive |
| 收集 Prefetch、排程、服務、自啟項、行程、網路連線、DNS 快取 | 記憶體擷取、全碟映像 |
| SHA-256 manifest、action log、監管鏈紀錄、驗證工具 | 數位簽章、RFC 3161 可信時戳 |
| AES-256 密碼加密的證據包 | 公鑰加密 |
| WinForms GUI ＋ CLI | 時間軸分析介面 |

## 驗收標準（來自 proposal，QA 依此出報告）

| 編號 | 項目 | 標準 |
|---|---|---|
| AC1 | 一鍵操作 | 依 SOP ≤ 3 步、≤ 10 分鐘完成匯出 |
| AC2 | 時間裁切 | 匯出事件 100% 落在指定時段 |
| AC3 | 體積 | 證據包比「整檔複製全部 EVTX」小 50% 以上 |
| AC4 | 證據召回 | 模擬攻擊的關鍵事件 ≥ 90% 可在證據包中找到 |
| AC5 | 抗清除 | Security log 被 `wevtutil cl` 清除後，仍可從 vault 取回清除前的事件 |
| AC6 | 完整性 | 每個檔案 SHA-256 重算 100% 一致；竄改任一檔案時驗證工具能指出 |
| AC7 | 優於現況 | 在相同 VM 情境下與「手動整檔複製 EVTX」及 KAPE 比較（步驟、時間、大小、命中率、是否附完整性證明），ForensiKit 至少在步驟數與證據包大小勝出 |
| AC8 | 外部驗證 | 至少 1 位業界或執法單位專業人士（優先 week 7 講師）審閱範例證據包並回饋可用性 |

## 評分項目對應

課程評分：問題 3、解法 5、市場規模 5、技術可行性 5、PoC 12（共 30）。每一項都要有拿得出來的證據：

| 評分項目 | 配分 | 用什麼證明 | 負責任務 |
|---|---|---|---|
| PoC（MVP） | 12 | VM 現場 Demo（含 log 被清除後仍能取回）＋ AC1–AC8 量測結果 ＋ 備援錄影 | T09a、T12、T13、T15、T16 |
| 解法 | 5 | 與手動複製、KAPE 的實測比較表（AC7）；與 EDR 的定位差異 | T17、T18 |
| 市場規模 | 5 | TAM／SAM／SOM 與商業模式（`docs/MARKET.md`） | T18 |
| 技術可行性 | 5 | 第 11 週就能跑的最小端到端版本（T09a）；全用 Windows 原生能力；CI 綠燈 | T01、T09a |
| 問題 | 3 | 講師訪談、2025 醫院勒索事件、Security log 預設 20 MB；講師對範例證據包的回饋（AC8） | T19 |
